# 班级聊天室：难度评估与 AI 开发任务书

> 日期：2026-09-20。依据当前仓库代码静态审查编写，原始设计方案，现已在 feat/classroom-chat 分支实现。实施差异、验证结果和回退步骤见 [交付与回退说明](classroom-chat-release-notes.md)；实际接口以 docs/api.md 为准。

## 1. 结论与开发边界

建议保留现有 Go 单进程 + React + SQLite 架构，新增站内 `/chat` 网页，在 `/navigation` 学习导航中提供“班级聊天室”卡片。学生在当前浏览器完成本场签到后，持服务端签发的学生凭证进入对应房间。消息只在服务器内存中限量暂存，教师后台可清空；重启后消息消失。

整体难度 **中等，约 3/5**。页面和导航入口较简单；主要工作是学生身份、考勤权限联动、实时连接生命周期及并发清理。无需独立聊天服务、Redis、外部 IM 或新部署端口。

以熟悉 Go/React 的一名开发者、AI 辅助实现且有人验收为假设：

| 工作 | 难度 | 估算有效工时 |
| --- | --- | --- |
| 学生凭证、签到事务、旧库迁移 | 中 | 1–1.5 天 |
| 内存房间、消息接口、SSE、限流和清理 | 中 | 1–1.5 天 |
| 学生页面、导航、教师管理 | 低至中 | 1–1.5 天 |
| 权限回归、并发测试、恢复兼容、实际部署验证 | 中至高 | 1–2 天 |
| 合计 | 中 | 4–6.5 个工作日 |

一天按约 6–8 小时有效工作计算，这是排期估算，不是交付承诺。仅展示收发消息的原型可能 1–2 天完成，但不能据此省略权限和并发验收。

## 3. 第一版产品规则（按此实现）

1. **按课堂场次分房间**：roomId = attendance session ID；界面显示班级、课程和本次课堂时间。同班下次签到进入新房间，不能看上次聊天。
2. **资格**：当前场次 active、未删除，学生和班级未删除，学生属于该班，考勤为 present/late，且持有绑定该学生和该场次的有效凭证。资格必须由后端校验，不能信任 URL、localStorage 或提交的姓名。
3. **结束语义**：第一版“结束考勤”同时结束聊天室并清除消息。教师如希望继续聊天，应保持场次进行中。未来如需要“停止签到但继续聊天”，再增加独立课堂状态，不在本版隐式实现。
4. **内容**：实名纯文本消息，显示姓名、发送时间、教师标识（教师消息）。最多 500 个 Unicode 字符，允许换行和 emoji；不做图片、附件、语音、私聊、撤回、输入状态、已读回执或全文搜索。
5. **教师能力**：在后台新增“聊天室”管理页，可选择当前班级房间、查看消息、发言、暂停/恢复学生发言、清空当前房间。无需教师伪装学生或签到。
6. **暂存**：每房最多 500 条且正文 UTF-8 总字节数不超过 1 MiB；消息最长存活 2 小时，以先达到的限制为准。关闭课堂、删除场次、教师清空或进程重启均会清除消息。
7. **入口**：导航页增加固定内置卡片 `/chat`，与教学网站卡片并列，新标签打开；不改导航链接表和外链校验规则。未签到点击后提示前往 `/checkin`，不显示聊天内容。没有外链时也应显示聊天卡片。
8. **启用**：部署开关 `CHAT_ENABLED` 默认 false，显式开启后显示入口并初始化聊天服务；关闭时学生/教师聊天接口返回 503 + `chat_disabled`。开启状态下房间随有效场次按需创建，容量满时不影响签到。
9. **人数**：只展示在线人数，不展示完整在线学生名册；同一学生多个标签按一个人计数，教师另计。
10. **同一浏览器**：一个学生身份，可开最多两个聊天标签；另一学生在该浏览器成功签到后替换身份并撤销旧凭证、关闭旧连接。机房换人时提供“退出学生身份”按钮，不修改考勤。

身份可信度边界：现有自助签到是选择姓名并确认，没有学生密码。新增凭证能证明“此浏览器完成过该学生的签到”，不能证明操作者本人身份，不能彻底防止先冒名签到。第一版沿用现有课堂信任模型，不擅自引入学生账号或动态签到口令。

## 4. 技术方案

采用 **HTTP POST 发消息 + SSE 接收事件 + 有界内存房间**。

浏览器原生 EventSource 支持同源 Cookie、断线重连，符合单向服务端推送需求；发送和教师操作仍走现有 JSON API。不引入 WebSocket 依赖和升级代理配置。不要用每秒轮询整个聊天列表。

数据库只保存学生凭证，沿用原有考勤/名单作为授权事实。消息、在线状态、限流桶、去重缓存和暂停标记位于内存。重启后暂停状态恢复默认“可发言”，后台及部署说明需明确这一点。

### 4.1 学生凭证与签到事务

新增 `student_chat_sessions` 表，建议字段：

| 字段 | 含义 |
| --- | --- |
| token_hash TEXT PRIMARY KEY | 32 字节加密随机 token 的 SHA-256，仅存哈希 |
| student_id INTEGER NOT NULL | 学生外键 |
| attendance_session_id INTEGER NOT NULL | 本场次外键 |
| created_at INTEGER NOT NULL | UTC Unix 秒 |
| expires_at INTEGER NOT NULL | UTC Unix 秒，签发后 4 小时固定到期 |

为到期清理、场次撤销、学生撤销建立相应索引。外键级联处理永久删除；软删除及状态修改需显式撤销。第一版每学生每场只保留一个有效凭证，新签发撤销旧凭证。所有清理批次有上限，不在每条消息中扫描整表。

Cookie 名 `classorbit_student`，Path `/api/public`（覆盖签到接口，以便同浏览器换人时撤销旧凭证），HttpOnly，SameSite=Strict，HTTPS 下 Secure，MaxAge 与到期时间一致。不要写入 localStorage、查询参数或前端可读字段，不复用教师 Cookie。

改造签到流程：预生成随机 token → 事务内校验本场有效与学生归属 → 条件更新 absent 为 present → 插入凭证并撤销被替换凭证 → 提交 → Set-Cookie。只有事务成功才返回签到成功，不增加公开响应里的 token。`checkInResponse` 可增加 sessionId/classId 等非敏感上下文，并同步前端类型和 API 文档。聊天关闭时保持原签到行为。

必须将资格检查、条件更新和凭证写入放在同一事务，避免课堂关闭与签到并发造成越权。处理“提交已成功但响应丢失”时，不可对任意提交已签到姓名的人直接补发身份。

恢复规则：

- 刷新、打开新标签、普通重启：Cookie 未过期且数据库校验有效即可重新进入；重启只是消息清空，不必重新签到。
- Cookie 丢失、过期、换设备、教师代签、签到响应丢失：显示“请联系老师重新开放本人签到”。第一版通过教师把本人考勤改为 absent，再由本人签到恢复；该动作修改考勤时间，应在界面说明，保留现有审计规则。不得仅凭 classId/studentId 或 present 状态领取凭证。
- 考勤改为 absent/leave、班级/学生/场次删除或场次结束：立即撤销相关凭证并断开连接。恢复历史考勤不能恢复凭证或消息。
- 数据库恢复：候选库中删除全部学生凭证，切库成功后清空全部内存房间；任何恢复失败/回滚路径也不能让已撤销凭证重新生效。

### 4.2 房间与消息模型

`ChatHub` 管理房间，各房间单独串行化写入、清空、快照和订阅操作，避免一把全局锁承担网络 I/O。网络发送必须在锁外。

建议消息模型（同步到 models.go/types.ts）：

```ts
type ChatMessage = {
  id: string                 // room epoch + 单调 seq，服务端生成
  seq: number
  clientMessageId: string    // 发送者生成 UUID，用于重试去重
  sender: { role: 'student' | 'teacher'; id: string; name: string }
  text: string
  createdAt: string          // 服务端 UTC ISO 8601
}
type ChatSnapshot = {
  roomId: number
  epoch: string              // 重启/清空后更换，随机不可复用
  latestSeq: number
  messages: ChatMessage[]
  onlineStudents: number
  paused: boolean
}
```

学生接口不接受指定发送者或任意 roomId，身份和房间来自凭证。昵称、班级、发送时间均由服务器生成；教师身份来自现有教师认证。消息 id 为字符串，避免前端整数精度与跨重启重复问题。

同一房间、发送者、clientMessageId 在 10 分钟去重窗口内重试返回原结果；相同 key 不同正文返回 409。去重表也有全局/单房容量和 TTL，淘汰后不保证 exactly-once。客户端遇到不确定发送结果保留相同 key 重试，不能自动生成新 key。旧 epoch 的请求不得重新投递到清空后的房间。

## 5. 接口契约

学生端仍位于 `/api/public/`，这里的 public 仅表示不要求教师登录。**以下学生路由全部执行专用学生鉴权**，不因前缀公开就直接返回数据。教师路由沿用 requireTeacher。

| 方法与路径 | 权限 | 结果/参数 |
| --- | --- | --- |
| GET `/api/public/chat/session` | 学生 | 当前身份、roomId、课堂名称、expiresAt、paused；不返回 token |
| DELETE `/api/public/chat/session` | 学生 | 撤销当前凭证、断开其连接、清 Cookie；重复退出幂等 |
| GET `/api/public/chat/events` | 学生 | SSE，首次/重连发送 snapshot，再发送增量 |
| POST `/api/public/chat/messages` | 学生 | `{text, clientMessageId, epoch}`；成功 201 + message，重复 200 |
| GET `/api/chat/rooms?classId=...` | 教师 | 当前活动房间列表和容量/消息/在线统计，不暴露学生凭证 |
| GET `/api/chat/rooms/{sessionId}/events` | 教师 | SSE，用于后台查看 |
| POST `/api/chat/rooms/{sessionId}/messages` | 教师 | 同学生发送参数，教师可在暂停时发言 |
| PATCH `/api/chat/rooms/{sessionId}` | 教师 | `{paused: boolean}`；返回最新房间状态 |
| DELETE `/api/chat/rooms/{sessionId}/messages` | 教师 | 清空并返回 `{ok:true, epoch:新值}` |

错误结构沿用 `{error: string}` 并可选扩展 `code`，前端按 code/status 处理，不匹配中文文案。统一约定：401 无凭证/过期；403 已无资格；409 房间暂停、epoch 过期或 key 冲突（不同 code）；404 教师指定房间不存在；413 请求体过大；422 正文无效；429 限流/连接配额（Retry-After）；503 功能关闭/全局容量已满/维护中。

首次连接前先请求 session，处理 401/403 后不建立 EventSource。连接出错时关闭旧实例，再以 1、2、4、8、最多 30 秒并加随机抖动重试；每次先校验 session。不要让浏览器自动重连与手动重连两个机制并行。稳定连接后重置退避，页面卸载/身份失效必须释放连接。

SSE 事件：`snapshot`、`message`、`presence`、`room_state`、`room_cleared`、`session_revoked`、`room_closed`。第一版不提供无限事件重放：每次重连都下发当前最多 100 条 snapshot，覆盖客户端列表，明确忽略 Last-Event-ID。取快照与注册订阅必须原子化，确保二者之间的消息不会丢失；快照后只发送更大 seq 的事件。

快照/事件携带 epoch；清空更换 epoch、丢弃未发送旧队列，前端同步清空消息、待发重试和去重状态，并忽略旧 epoch 的 HTTP 回包及事件。TTL 到期或容量淘汰时发送 `history_trimmed` 事件和 firstSeq 下界，防止在线页面长期保留已过期消息。客户端按消息 id 去重，不能假设 POST 响应一定早于 SSE。

## 6. 性能与生命周期（必须实现）

以下为初始默认值，集中定义并校验；除启用开关外可以先作为常量，不需要复杂配置页。

| 项目 | 初始上限/规则 |
| --- | --- |
| 正文 | 500 Unicode 字符，JSON 请求体最多 8 KiB |
| 历史 | 每房 500 条、正文 1 MiB、TTL 2 小时，取最严格约束 |
| 快照/前端 DOM | 快照 100 条；前端最多保留 200 条 |
| 学生发言 | 每学生每秒 1 条、突发 3 条；每房每秒 20 条、突发 40 条 |
| 并发容量 | 全局 10 房间、500 连接；每房 100 连接；每学生 2 连接；教师总共 10 连接 |
| 去重缓存 | 每房最多 2,000 项、10 分钟，清空时重置 |
| 慢客户端队列 | 每连接最多 64 个事件且最多 256 KiB，达到任一上限即断开 |
| 网络 | 每 20 秒 SSE 心跳；每次写入 10 秒超时；禁止锁内等待网络 |
| 定时清理 | 每 60 秒淘汰到期消息/去重/凭证，关闭房间立即清除 |

发送/连接鉴权可做索引查询，但 SSE 心跳不逐连接查询数据库。对在线学生的资格兜底核验按房间每 30 秒批量读取，变更接口在事务提交后立即撤销相应连接。鉴权与订阅、删除与投递之间必须通过短生命周期锁/版本检查串行化，确保撤销接口成功后不再接受该身份发言或向它排队新消息。

房间广播复杂度 O(在线连接)，内存上界由消息、队列、房间数量、凭证和去重容量共同约束。不能只限制数据库条数却放任 channel、map 或 DOM 增长。连接队列优先引用共享不可变编码结果；监控字节数，不假设 500 字符等于 500 字节。

### 必须处理的现有运行时冲突

1. **维护锁**：SSE 不得全程持有 `maintenanceMu.RLock()`。只在初始鉴权+注册时短暂持锁；流循环不访问数据库。后续数据库核验也使用短读锁，不持跨网络的锁。教师 SSE 同样适用。只对精确匹配的流路由调整维护/鉴权路径，不能整体绕过保护。
2. **恢复排他**：恢复获得维护写锁后先停止接入并取消所有流，终止流循环不能依赖再次获取维护读锁；清空聊天内存后再安全替换数据库。所有错误出口都恢复服务状态。已存在的自动备份锁策略保持兼容。恢复失败也允许丢失临时聊天消息，但不能卡住恢复。
3. **HTTP 超时**：使用 `http.ResponseController` 为 SSE 单独清除长期写 deadline，并在每次 Flush 前设置短写 deadline；保留其他接口原来的 5 分钟限制。不支持 Flush/deadline 时给出明确错误，不能悄悄退化成长时间阻塞。
4. **关机**：先 cancel Hub、关闭流和定时器，再执行 HTTP Shutdown，避免长连接占满 10 秒退出窗口。测试实例也必须能完整关闭。
5. **代理**：响应 `Content-Type: text/event-stream`、`Cache-Control: no-store`、`X-Accel-Buffering: no`；代理禁用 SSE 缓冲，读取超时大于心跳周期（例如 75 秒）。用实际 Nginx/Caddy 路径验证，开发环境沿用 Vite `/api` 代理。
6. **教师会话失效**：教师退出、改密、凭证过期需使其流失效；至少每 30 秒批量/缓存式复核，不能建立流后永久绕过教师认证。恢复时立即关闭。

清空语义：暂停房间事件写入 → 生成新 epoch → 清空消息/去重/待推送旧消息 → 广播清空事件 → 恢复接收。清空不会结束课堂或撤销学生资格；用户会话可能已经收到或截图的内容无法远程收回。清空与发送并发时以服务端串行顺序为准。

清空/暂停操作写现有 audit_logs，仅记录操作者、roomId、动作、清除数量，不记录聊天正文或 token。数据库审计失败时操作返回失败且不执行清空/暂停；实现中用短房间管理锁保证审计与操作顺序，避免持有广播锁等待 SQLite。聊天正文不进入日志、备份、浏览器持久化缓存。

## 7. 前端与安全细节

- `StudentChatPage`：顶部显示班级、本人姓名和返回导航；中部消息列表；底部多行输入、字数提示、发送按钮；底部状态可显示连接中/重连中/暂停发言/课堂已结束。
- Enter 发送，Shift+Enter 换行；中文输入法组合输入期间不得触发发送。移动端键盘弹起仍可看到输入框。发送失败保留正文并允许手动重试。
- 用户在底部才自动滚动；阅读较早内容时显示“有新消息”，不要强行抢滚动。不要对每条消息弹全局 toast。
- `ChatManagementPage`：复用 TeacherApp 班级选择器；清空前确认当前班级和不可恢复后果；有成功/失败反馈。这里的确认是未来产品交互要求，不是开发前的授权步骤。
- 单独实现学生聊天请求封装，或给 api helper 增加鉴权域选项；学生 401 不触发 `classorbit:unauthorized` 教师退出事件。
- 消息只作为 React 文本节点渲染，保留换行，不允许 HTML/Markdown 或 dangerouslySetInnerHTML；首版不自动识别外链。
- 所有带 Cookie 的聊天写操作（含教师控制）校验 Origin 与配置的可信公开源匹配，不开放通配凭证 CORS。明确处理无 Origin 的受控测试客户端；生产浏览器写入拒绝缺失/不匹配 Origin。可信源配置不能直接相信任意 X-Forwarded-Host。
- 同源上传教学网页具有同源脚本能力，HttpOnly 并不能阻止同源脚本调用 API；本版沿用“教师上传内容可信”假设，不宣称能隔离恶意同源脚本。若将来允许学生上传脚本，需要独立域名沙箱。
- 保留全局 `connect-src 'self'`，SSE 不需放宽 CSP。学生身份信息与 SSE 禁止缓存；不在日志中输出 Cookie 或请求正文。
- 按学生身份限流，IP 只作宽松兜底，避免整个机房共用 NAT 被误封。教师控制操作也需要合理限流。

## 9. 必须通过的验收用例

| 类别 | 用例与预期 |
| --- | --- |
| 权限 | 无 Cookie/伪造 Cookie 读写失败；改 URL/studentId 不跨房间；学生调用教师清空失败 |
| 签到 | 正常签到原子签发；并发重复签到最多一个成功；关闭场次与签到并发不越权 |
| 身份 | 新标签身份保持；退出撤销；同浏览器换人旧连接关闭；无凭证的已签到学生不能自助冒领 |
| 状态 | present/late + 凭证可入；absent/leave 不可；删除/结束立即拒绝并断开；恢复历史记录不恢复聊天 |
| 消息 | Unicode 限长、空白拒绝、超大请求拒绝、HTML 原样显示、中文输入法不误发 |
| 去重 | HTTP 响应/SSE 到达顺序互换不重复；超时同 key 重试不重复；同 key 不同正文冲突 |
| 清理 | TTL/条数/字节限制生效；无活跃学生的房间也可回收；清空与发送/重连并发不复活旧消息 |
| 网络 | 断线重连获取有界快照；过期身份停止重连；慢客户端断开；连接和限流 map 随退出回收 |
| 维护 | 有学生和教师 SSE 时能恢复数据库，无死锁；恢复成功/失败均释放资源；恢复后的旧凭证不可用 |
| 重启 | 消息丢失，普通重启后有效凭证仍可进入；暂停状态按文档恢复；Shutdown 不等待流自然到期 |
| 兼容 | 原签到、积分、名单、外链/上传教学页、教师登录、备份及旧库迁移无回归 |

性能验收必须在实际机器及代理链路上执行并记录配置。目标场景：60 名学生同时在线、房间稳定总计 10 条/秒、持续 30 分钟；另测 5 房间共 300 连接、每房 5 条/秒，以及受限的 500 连接峰值。每次注明浏览器/压测客户端、CPU、内存、网络和版本。

初始验收目标（不是已验证性能）：正常连接的发送到接收 P95 < 500 ms；签到/积分接口 P95 相对同环境无聊天室基线增长不超过 20%；容量满后返回明确错误而不导致服务失控；达到存储上限后，内存和 goroutine 数不随时间持续增长。测试同时覆盖大消息、慢客户端、反复断连和清空。未达标应定位瓶颈或降低公开支持容量，不能只写“理论上支持”。

## 10. 给后续 AI 的执行指令

请先阅读本文件及 CONTRIBUTING.md，复核代码是否已变化，再按四个阶段实施班级聊天室。维持 Go 单体、React 和单库 SQLite；消息只放有界内存；先做身份和权限，再做实时消息与页面。每阶段完成后执行相关验收，最后执行完整回归和部署性能验证。

不要用前端签到标记代替服务端凭证，不要凭已签到姓名直接补发身份，不要把学生接口放在 public 路由后省略鉴权，不要让 SSE 长期持维护锁，不要让内存队列无限增长。不要引入 Redis、微服务、第三方 IM、附件或新的学生账号系统。遇到代码与本文不一致时先说明具体差异并采用兼容方案。

交付应包含：实现代码、迁移和回归测试、接口文档、部署开关和代理说明、实测性能与限制、明确的消息清理说明。验收失败或未实测的项目要如实列出，不能把原型完成表述为生产可用。
