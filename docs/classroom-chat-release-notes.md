# 聊天室交付、验证与回退

## 回退基线

开发起点：`v1.8.8`，提交 `cce34783a05110414b53cddab81a332234c00db2`。2026-09-20 使用 `git ls-remote` 核实 GitHub `origin` 上的标签指向同一提交。当前功能位于 `feat/classroom-chat`，未改动旧标签，未发布生产版本。

Git 标签包含代码，不包含学生名单、积分、考勤或上传的教学网页。聊天开发只使用测试临时数据库，未连接生产数据库。

## 使用与数据规则

设置 `CHAT_ENABLED=true` 并重启后，学生导航显示 `/chat`，教师后台显示聊天室管理页。默认关闭；普通签到与外链导航不依赖聊天室。每次考勤场次是独立房间，结束考勤同时结束聊天。

学生在当前浏览器成功自助签到后获得 4 小时学生 Cookie；Cookie 丢失、换设备或教师代签不能仅凭姓名补领，需教师把本人重新设为缺勤后由本人签到。该操作会重置本人的签到时间。现有选姓名签到的信任模型不变，不等于学生密码认证。

消息为实名纯文本，最多 500 个 Unicode 字符；单房最多 500 条及 1MiB 正文，存活不超过 2 小时（无人操作时清理任务最多延迟 30 秒）。只保存内存，清空、结束课堂、重启或恢复数据库后不可恢复。浏览器不把消息保存到 localStorage。数据库只保存凭证哈希和管理审计，消息正文不进入数据库、审计或备份。凭证过期按批次清理，软删除和考勤资格修改在同一事务内撤销凭证。

教师可发言、暂停/恢复学生发言、清空消息。暂停状态保存在内存，重启默认恢复可发言。清空不会修改考勤和积分。已被学生截图或自行保存的内容无法远程收回。

## 实施取舍

- 使用原生 SSE + POST，不引入依赖或外部服务。刷新/重连取得最多 100 条、最多约 200KiB 的快照；前端最多保留 200 条。
- 全局 10 房间、500 连接，每房 100 连接，每学生 2 连接，教师总计 10 连接。容量是防失控上限，不是对任意服务器的性能保证。
- 有界 Hub 使用一个短内存锁；锁内不做网络或数据库 I/O。HTTP 身份变更与聊天接入通过独立短授权锁串行化。SQLite 本就只有一个业务连接，因此本版不增加每房多层锁。小请求体先在锁外读取，防止慢上传独占授权锁。
- Cookie 路径为 `/api/public`，覆盖签到接口，保证同浏览器换人可以撤销旧身份。原方案更窄的 `/api/public/chat` 无法在签到时读取旧 Cookie。
- TTL/容量淘汰只广播 `history_trimmed` 下界，不重传全部历史。清空更换 epoch，客户端丢弃旧 epoch 回包。
- SSE 在鉴权和订阅后释放维护锁，流循环不访问数据库。恢复数据库关闭所有聊天连接、撤销学生凭证；恢复前安全副本也不保留已撤销的学生凭证。
- 终止事件由连接关闭表达，客户端再次查询身份/房间后展示结束或失效状态，不实现无用的终止事件重放。
- 学生消息限流、房间总速率、管理操作限流、队列条数/字节、去重缓存和前端 DOM 均有界。

## 代理与开发环境

同源代理保持 Host 即可；代理改写 Host 时设置 `CHAT_ORIGIN` 为浏览器真实访问源，例如 `https://class.example.com`（无末尾斜杠）。浏览器写入必须包含匹配 Origin。Vite 开发使用 `/api` 代理，如实际转发 Host 不一致，设置 CHAT_ORIGIN 为 Vite 的完整访问源。

Nginx 示例（与原 `/api` 规则合并）：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 75s;
}
```

Caddy 原生识别 `text/event-stream` 并及时 flush。应保留 Host 并在实际公网/学校网络上再验收连接稳定性；本机测试不等同于生产链路压测。

## 升级与回退

数据库结构从 4 追加迁移到 5。新程序启动时，在修改旧库之前使用一致性 `VACUUM INTO` 生成 `backups/classorbit-before-schema-5-*.db`；备份失败即终止启动。该文件权限 0600，独立于日常自动备份保留策略，不会被 14 天清理任务删除。新建空库不产生无意义备份；同结构重启不重复备份。

正式部署前仍建议从现有后台下载备份并保存到服务器之外。首次升级后检查启动日志中的回退备份路径和文件实际存在。

若仅需要关闭聊天室：设 `CHAT_ENABLED=false` 并重启。无需降级数据库，已产生的正常考勤/积分不丢失。

若需要回退整个版本：

1. 停止新版本，保留当前数据卷完整副本（包括 WAL/SHM，停机后复制），不要删除数据卷。
2. 使用升级前的 schema 4 备份恢复到独立数据目录/新卷，先在隔离端口验证 `v1.8.8` 可启动及名单、积分、考勤正确。
3. 将代码/镜像固定到 `v1.8.8`/`1.8.8`，用已验证的旧库启动；切换流量前确认文件名、目录所有者及权限。
4. 保留新库副本，避免覆盖升级后产生的数据。恢复升级前副本会丢失升级后新增业务记录；有新记录时应先评估数据迁移，不能直接覆盖。

旧程序会拒绝 schema 5 数据库，因此仅切 Git 标签/镜像不足以回退。不要通过手改 schema_migrations 伪装降级，不要使用 `docker compose down -v`。

## 测试与限制

自动测试覆盖凭证原子签发/失败回滚、重复和并发签到、同浏览器身份替换、课堂隔离、缺勤/请假/删除/结束后撤销、教师退出、暂停、清空并发、去重、字数/体积限制、慢客户端断开、过期清理、审计失败不清空、旧库升级前备份及 SSE 在线时恢复数据库。

浏览器通过本机临时服务和虚拟学生验证：签到倒计时、导航新标签、学生到教师实时消息、教师暂停和发言、清空确认内容、390×844 手机排版。页面未出现聊天室脚本错误。未操作生产数据。

前端 12 个测试文件、25 项测试及生产构建通过；Go 静态检查、版本检查和 diff 空白检查通过。最终 `go test -race ./backend` 通过（约 85 秒）。后端 SSE 测试需要本机监听权限；沙箱禁止监听时需要在允许 localhost 监听的环境运行，不能将该环境限制当作测试通过。

持续测试曾运行 60 学生、10 条/秒约 9 分钟：第 4–9 分钟 Go 堆约 6.4MB，goroutine 保持 369；这些数值包含同进程 HTTP 测试客户端，不代表纯服务器 RSS。该轮主动中止，不能计作完整 30 分钟稳定性验收，也没有最终 P95。完整长测可复现：

```bash
CHAT_LOAD_TEST=1 CHAT_LOAD_DURATION=30m go test ./backend -run '^TestChatLoad$' -v -timeout 35m
```

开发机为 macOS arm64、Go 1.27；测试无 race 时压测，race 单独执行。生产硬件、学校共享网络、真实代理、备份时负载与签到/积分 P95 相对基线仍需部署环境确认。未将本机结果描述为生产容量承诺。

### 最终容量与代理实测

2026-09-20，本机无 race，实际 HTTP/SSE 连接，每组 30 秒：

| 场景 | 消息发送 | 实际/预期投递次数 | 接收 P95 |
| --- | --- | --- | --- |
| 1 房间、60 学生、10 条/秒 | 300 | 18,000 / 18,000 | 3.2ms |
| 5 房间、300 学生、每房 5 条/秒 | 750 | 45,000 / 45,000 | 2.5ms |
| 5 房间、500 学生、每房 5 条/秒 | 750 | 75,000 / 75,000 | 3.7ms |

500 连接达到上限后，第 501 个连接按预期返回 429。三组测试全部通过（总计约 91 秒）；500 连接组 Go 堆约 22.2→23.1MB，包含同进程客户端，不是服务端独立 RSS。

另外通过官方 Caddy 2.10.2、本机独立代理端口完成签到、SSE 快照、发送、接收与清空验收。单条消息发送至接收 0.9ms，证明该配置未缓冲 SSE；这不是并发代理压力测试。预览班级均为虚拟学生。
